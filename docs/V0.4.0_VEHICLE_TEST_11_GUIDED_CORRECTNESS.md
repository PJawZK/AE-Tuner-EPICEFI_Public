# AE Tuner EPICEFI 0.4.0-vehicle-test.11 — Guided correctness candidate

## Status

`0.4.0-vehicle-test.11` is a read-only, unaccepted physical-test candidate.

It is based exactly on the validated `.10` runtime-rescue source head:

`ec626aa1d94e4bd898daa1fc82b8830370e2860d`

The `.10` runtime repair is retained. This candidate changes only the two Guided correctness defects demonstrated by Archive 13 plus regression/identity coverage.

Do not paste or apply a Blend Duration proposal while validating this candidate.

## Physical evidence that caused this revision

Archive 13 showed that `.10` restored the previously broken runtime path:

- passive ECU data was live and reportable;
- Guided received samples and produced explicit outcomes;
- audio cues opened/completed;
- evidence/recovery export worked.

However two correctness defects were physically visible.

### 1. TPS guide marker chased live TPS

The adaptive gauge used live TPS as a substitute baseline whenever the Guided engine did not expose a baseline. Therefore the visual target became:

`live TPS + desired TPS step`

and moved as the pedal moved.

The engine also exposed its rolling READY baseline, so gradual road/load correction could move the driver-facing marker before the opening was frozen.

### 2. Inactive fallbackMap could define the Blend Duration measurement anchor

The adaptive engine selected the largest `fallbackMap - MAP` gap from attempt samples without requiring current-event MAP prediction to be active.

Archive 13 contained large stale pre-prediction gaps. Event 1, for example, contained approximately:

- prediction inactive: MAP 51.17 kPa, fallbackMap 112.80 kPa, gap 61.63 kPa;
- later current-event prediction active: MAP 73.02 kPa, fallbackMap 96.10 kPa, gap 23.08 kPa.

Using the stale 61.63 kPa gap made the 90% catch-up target approximately 106.64 kPa and caused a false failure before throttle release. Using the current-event prediction-active 23.08 kPa gap makes the target approximately 93.79 kPa, which the recorded event reached while the pedal remained held.

Therefore Archive 13 Blend Duration values are not accepted tuning evidence.

## `.11` behavior

### Driver TPS guide

- SETTLING / READY: no absolute TPS marker or guide band is drawn.
- The UI continues to show the configured relative guide, e.g. `+20 TPS points`.
- OPENING_PENDING: the immediately preceding rolling baseline is frozen and may now define the visual guide marker.
- CAPTURING: the frozen pre-opening baseline continues to define that marker.
- A missing baseline never falls back to current TPS.
- The marker remains advisory; the captured natural held TPS and actual relative step remain authoritative for the event.

### Blend Duration measurement anchor

A sample may update the peak initial measured-MAP to fallbackMap gap only when:

`MAP_PRED_ACTIVE == true`

Inactive/stale fallbackMap values remain present in raw telemetry and compact trace rows but cannot define the measurement anchor or 90% MAP catch-up threshold.

## Regression coverage

The active regression suite now verifies:

- READY does not expose the rolling TPS baseline as a moving driver target;
- OPENING_PENDING exposes a finite frozen baseline;
- that frozen baseline does not move with later TPS input;
- no-baseline TPS gauge target/band values are NaN/hidden rather than `live TPS + desired step`;
- a finite frozen baseline produces a fixed advisory marker;
- an Archive-13-shaped stale 61.63 kPa inactive gap cannot become the measurement anchor;
- the subsequent 23.08 kPa prediction-active gap can complete the catch-up while throttle remains held;
- the compact trace identifies the active 23.08 kPa measurement anchor;
- prior adaptive grouping, lifecycle, audio, evidence and read-only regressions remain in the validation suite.

8. Large pre-prediction fallbackMap gaps must remain visible only as raw trace evidence; they must not become `gap_kpa` measurement anchors.

10. Do not paste/apply a proposal during this validation.
